# 口播精简 AI 使用记录

交付版｜2026 年 11 月 7 日

### 使用范围与分工

本项目使用 Codex 辅助后端、前端、媒体处理、测试、问题定位与文档整理。本轮还核对了代码、版本记录和交付证据，使产品说明与当前实现保持一致。

我使用 Claude Code 和 Codex 辅助编程，并开展完整的 Auto Research Workflow。在这个项目中，我把握方向与交付要求，针对具体交互提出反馈，例如补录同时支持上传和直接录音、多条建议重新布局。AI 将这些反馈落实为实现与检查，我再根据结果继续审阅和调整。

### 产品内部模型与非模型工具

- faster-whisper medium：CPU int8、本地转写及词时间戳。口音、人名和地名仍有误识别，需人工校对。

- Qwen2.5-7B-Instruct Q4_K_M：本机 llama.cpp 推理，生成相关性和编辑建议；限制 ID 与操作格式，保护必留，失败明确回退规则。

- Demucs htdemucs：分离人声与背景，供试听和转写使用；分离后的识别效果仍需复核。

- eSpeak NG：用于早期原创合成旁白样例；最终 Demo 使用公开授权的真人素材。

- FFmpeg/ffprobe：承担转码、裁剪、拼接和媒体核验，是实际产出视频的工程工具。

## AI 产出后的修改与检查

审阅与测试推动了几类修改：保护并发编辑与旧成片版本，保存草稿并隔离项目，将补录请求绑定到具体句子；随后加入直接录音、WAV 转换、麦克风释放和建议列表滚动。根据后续需求，补录上限放宽至每句 60 秒，长于原句时延长末帧并顺延字幕。这些实现和自动化检查由 AI 辅助完成，我的主要贡献是方向把控、交互反馈与结果审阅。

最终 Demo 的真实 Qwen 推理用时 148.2 秒，生成 32 项候选；经接受、拒绝和手动调整后，输出为 27.588 秒。布局回归另用确定性候选，补录测试采用授权样例音频输入。历史 25.188 秒结果及其 199.9 秒推理记录按原版本保存，详见最终验证报告。

### 人的判断与闭环反馈

我的判断是底层模型能力最核心，应用应把价值落在目标表达、可靠执行与可检查的结果上。本项目中，“补录上传与直接录音”和“多条建议布局”的反馈进入实现，再通过测试与审阅检查结果。这体现了我使用 AI 的方式：先明确方向，再抓住具体问题持续反馈，直到形成可交付的结果。

### 工具分工

Claude Code 和 Codex 是我实际使用的编程与研究助手；本项目有记录可追溯的开发、检查和交付工作主要由 Codex 完成。Whisper、Qwen、Demucs 则是产品运行组件。产品观点来自我的使用经验，本轮文字整理和润色也使用了 AI。
